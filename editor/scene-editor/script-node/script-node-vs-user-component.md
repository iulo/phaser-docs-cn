# 脚本节点与用户组件的区别 {#page-title}

Phaser Editor v5 · [英文原文](https://phaser.io/oss/docs/phaser-editor/scene-editor/script-node/script-node-vs-user-component)

现在您有两种机制来分配对象的行为:脚本节点和用户组件,您必须决定何时使用其中一种。在本章中,我们试图为您提供一个小的向导。

**何时使用用户组件 ?**

许多用户发现用户组件非常方便,因为您可以立刻编辑其属性, 与对象属性相同。 您不需要浏览对象的节点树。 组件也是Phaser API中熟悉的哲学。 然而, 用户组件主要有限制: 它与对象有一对一的关系。 这意味着您只能为对象指定单一类型的组件, 所以它应该作为一个单元执行整个行为 。

这些是一些使用用户组件的建模行为的例子:

* 用于添加到图示中的 ** Autoplay Animation ** 用户组件。 它具有一个自动播放的** animationKey** 属性。 由于您每次只能播放一个动画, 它非常适合用户组件的一对一关系限制 。
* ** 边界锁定器** 部分,含**anchorTo** 有价值的属性,例如: `left`, `top`, `right`, `bottom`。此组件将自动将对象重新定位到响应场景。由于对象只有一个位置,它适合用户组件的一对一限制。
* 一个 ** DurationConfig ** 组件, 包含关于动画持续时间的信息。 您可以把它添加到一个执行动画的脚本节点或预制体中。 这意味着您可以使用用户组件为某个动作或对象添加额外的配置 。

**何时使用脚本节点?**

脚本节点是逻辑游戏对象,你可以制作它们预制体。编辑器中的预制体系统很强大,可以在等级关系中表达复杂的行为。此外,你还可以把脚本节点添加到其他对象上,也可以在场景中添加。然而,你很容易开始滥用脚本节点的使用,并制作大型的逻辑节点分级。我们认为现在这不是一个好主意,但最终还是由你决定。

脚本节点非常灵活,可以建模不同的行为,然而,它对我们使用事件和行动的概念效果更好,也就是说,你创建了一组脚本节点来覆盖游戏中的事件,另一组脚本节点来涵盖动作。这样,你就可以将事件和行动结合起来来创造复杂的行为.

如果您查看了 [@phaserjs/editor-scripts-quick](https://www.npmjs.com/package/@phaserjs/editor-scripts-quick) 库, 它包含一系列覆盖游戏中常见事件和动作的脚本节点。 您可以使用此库作为您自己的脚本节点的基础 。

以下是您可用此库表达的一些行为:

* 当点击按钮时, X 场景就会开始.
* 点击按钮时,它会播放一个声音.
* 当两个物体碰撞时,播放动画,播放声音,并摧毁第二个物体.
* 当场景开始时,对物体做一个淡出动画.
* 当场景开始时,将一个物体从屏幕的底端移动到其原位.

正如我们先前说过的, 脚本节点的使用时间和在小逻辑单元树上分割多少行为, 取决于您。 我们的建议是, 在制作复杂的脚本节点框架之前, 要保持简单, 首先从游戏中学习。

如果您是高级编码器,你可能会发现脚本节点太繁琐,而且你可能是对的。然而,也许你可以设计自己的脚本节点,以便团队中的其他人员能够更快地创建游戏原型.
